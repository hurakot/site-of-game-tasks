# Ограничения и планы

Документ описывает исходники текущей версии. Перечисленные исправления ещё не реализованы.

## Нет миграций БД

create_all создаёт отсутствующие таблицы, но не обновляет существующие. Alembic/Flask-Migrate не подключены. Перед изменением схемы нужна резервная копия, затем миграция или согласованное ручное изменение. Удалять базу допустимо только для одноразовых учебных данных.

В проекте две копии Course.db, версия Flask-SQLAlchemy не закреплена. Перед работой проверьте фактический путь через db.engine.url.database. SQLite foreign_keys явно не включается: объявления ForeignKey сами по себе не гарантируют проверку связей этим движком.

## Безопасность

- Регистрация и административное редактирование сохраняют пароль открытым текстом. Вход сначала ищет совпадение username и password; условие с `or userdata` допускает найденную запись. Импорт функций хеширования не означает их корректного использования. Нужны хеширование при записи, поиск только по username, проверка хеша и переход существующих пользователей на новую схему.
- Неверный вход включает введённые логин и пароль во flash. Административные формы показывают пароли. Это поведение нужно удалить.
- Ключ сессии и коды организаций находятся в исходниках. Нужны внешний секрет и управляемые приглашения.
- check_rights проверяет только роль. create_record не проверяет исполнителя и статус задания; report_view — доступ к отчёту; report_accept/report_cancel — организацию представителя.
- task_accept не проверяет Active и отсутствие исполнителя: прямым запросом можно переназначить задание. Нужна атомарная смена состояния с проверкой исходного значения.
- Принятие задания, зачёт/отклонение отчёта и удаление доступны через GET. CSRF-токенов нет. Нужны POST для изменений и CSRF-защита.
- object upload не защищён и позволяет перезаписывать файлы с предсказуемыми именами. Его следует удалить или закончить с проверкой прав.
- uploads публичны как static. Нет проверки реального формата, количества и размера изображений после декодирования; расширение jpg присваивается любым байтам.
- MAX_CONTENT_LENGTH не установлен, MAX_FORM_MEMORY_SIZE не обеспечивает заявленной защиты в Flask 2.0.3. Нужны работающие ограничения на сервере и в приложении.
- Нет ограничения попыток входа и требований к паролю; некоторые исключения показываются пользователю целиком.

## API

Это HTML-приложение без JSON REST API и OpenAPI. Авторизация сессионная, JWT нет.

Отсутствующие объекты часто не обрабатываются: first/get возвращает None, обращение к полям приводит к 500. Нужны 404, обработка невалидных полей и единый подход к rollback. Часть исключений регистрации/создания перехватывается без отката сессии.

Многие действия перенаправляют на request.referrer без проверки и запасного адреса. При отсутствующем Referer возможна ошибка формирования редиректа, при постороннем адресе — внешний переход.

### Ошибки зачёта отчёта

1. В `Report.query.filter(report.id_task == task.id_task, mercenary.mercenary.id_mercenary == report.id_mercenary)` сравниваются значения Python вместо колонок Report. При обычном соответствии получаются True/True: выборка может включить все отчёты, которые затем помечаются Done.
2. mercenary_did_task загружается до перевода текущего задания в Done. На первом зачёте список пуст, деление на его длину вызывает ZeroDivisionError. Позже текущая награда не включается в среднюю цену; используется целочисленное деление.
3. Статусы задания и отчётов фиксируются первым commit до расчёта рейтинга. Ошибка оставляет частично применённое действие.
4. Нет защиты от повторного зачёта: одно задание может повторно увеличить рейтинг.

Нужны фильтр по колонкам Report, объектные права, проверка исходных статусов, расчёт с учётом текущего задания, обработка пустого списка и одна транзакция.

### Статусы и связи

- Просрочка проверяется только при входе. Фоновой проверки и обещанного flash-сообщением исчезновения задания нет.
- Сертификат проверяется на занятость запросом, но у mercenaries.certificate_code нет UNIQUE: возможна гонка регистрации.
- Нет межтабличного ограничения «одна роль на пользователя».
- Удаление наёмника не задаёт явного бизнес-правила для его заданий и отчётов. Поведение следует определить и покрыть тестами.

## Эксплуатация

- В requirements.txt не хватает трёх используемых зависимостей; версия Python не закреплена. Нет автотестов и CI.
- Прямой запуск включает debug=True; серверу нужен WSGI-запуск, внешний секрет и отключённая отладка.
- Docker, конфигурация хостинга и автоматические бэкапы отсутствуют.
- SQLite и uploads локальны; при замене каталога/диска данные могут потеряться. Нескольким экземплярам понадобится решение для общей БД и файлов.
- Изображения сохраняются до commit, не удаляются при удалении отчёта/задания. Возможны потерянные файлы; нужна очистка.
- Пути вложений хранятся строкой через запятую. Для расширения лучше отдельная таблица вложений.
- GET object upload обращается к отсутствующему upload_image.html. Привязка изображения к модели оставлена комментарием.
- Bootstrap CSS 5.0.2 и JS 5.3.0 подключены с CDN; версии различаются, интерфейс зависит от доступа к CDN.
